# Coding Standards

- Prefer readable, typed, modular code over clever abstractions.
- Keep components focused and reusable.
- Use descriptive names and consistent formatting.
- Separate presentation, business logic, persistence, and transport concerns.
- Validate at system boundaries.
- Avoid duplicated logic and unnecessary dependencies.
- Handle loading, empty, error, and success states in interactive UI.
- Provide accessible labels, keyboard operation, focus visibility, and semantic HTML.
- Add tests for meaningful behavior.
- Update docs when contracts or architecture change.
- Do not use placeholder data in production output.
